# Spec: Обновление finam-trade-api SDK и переход на новый формат API-ключей

## Problem
Проект использует SDK `github.com/FinamWeb/finam-trade-api/go` на уровне релиза 2.14.0 (псевдо-версия `v0.0.0-20260401112026-402e726d2b7f`, коммит 01.04.2026). С тех пор вышли релизы 2.15.0–2.17.0. Ключевой из них — **2.15.0**, который вводит новый компактный формат API-ключей (`tapi_ak_...` / `tapi_sk_...`, ~40 символов вместо 1700+), помечает старые длинные ключи как Legacy и добавляет в auth-запросы поле `source_app_id`. Онбординг приложения и документация всё ещё описывают старый формат и ссылаются на устаревшие адреса портала. Кроме того, обновление токена сейчас реализовано «по таймеру» (повторный вызов `Auth`), тогда как API предоставляет стриминговый метод `SubscribeJwtRenewal` для автоматической выдачи новых JWT.

## Solution
Обновить зависимость SDK до последней версии, привести онбординг и документацию к новому формату ключей, начать передавать `source_app_id` при авторизации и перейти с таймерного обновления токена на стриминг `SubscribeJwtRenewal`. Логику приёма пользовательского ключа не меняем: эндпоинт `Auth` авто-определяет тип токена, приложение передаёт введённое значение в поле `Secret`, старые длинные ключи продолжают работать (обратная совместимость).

## Requirements

### 1. Обновление SDK
- Обновить `go.mod` до последней доступной псевдо-версии `v0.0.0-20260707135128-ee013ef14834` (коммит `ee013ef`, 07.07.2026).
- Модуль живёт в подкаталоге `/go` и не имеет semver-тегов — фиксируем по коммиту (`go get ...@latest`), не по тегу `Release-2.15.0`.
- `go mod tidy`; проект компилируется, все тесты и линтер проходят. Изменения SDK аддитивные — ломающих правок не ожидается.

### 2. Новый формат ключей — онбординг и документация (без изменения логики)
- `ui/setup.go`: обновить приветственный текст и ссылку на портал (`https://api.finam.ru/tokens/`), упомянуть новый короткий ключ `tapi_sk_...` и что старые длинные ключи теперь Legacy. Логику ввода/валидации не менять (валидация поведенческая — через `GetAccounts()`).
- `.env.example`: обновить ссылку и комментарий под новый формат; имя переменной `FINAM_API_TOKEN` остаётся (работает для обоих форматов).
- `README.md`: обновить ссылку на создание токена и добавить заметку о новом формате/Legacy.
- `CHANGELOG.md`: запись об апдейте SDK и поддержке нового формата ключей.

### 3. `source_app_id` при авторизации
- Ввести константу-идентификатор приложения (напр. `"finam-terminal"`) в `api/`.
- Передавать её в `auth.AuthRequest.SourceAppId` и `auth.SubscribeJwtRenewalRequest.SourceAppId`.

### 4. Переход на стриминг `SubscribeJwtRenewal`
- Первичный `Auth` сохраняется (нужен первый JWT и `TokenDetails` для списка счетов).
- Заменить таймерный `startTokenRefresh` на server-stream `SubscribeJwtRenewal`: в цикле `stream.Recv()` обновлять `c.token` присланными JWT.
- Устойчивость: реконнект с бэкоффом при обрыве/EOF стрима (стрим рвётся ~раз в 24ч), корректная остановка по отмене контекста и `Close()`.
- Обновить мок `MockAuthServer` (`api/testserver/`) — реализовать стриминговый `SubscribeJwtRenewal`; переписать `client_token_refresh_integration_test.go` под стримовую модель.

### Не включаем (non-goals)
- Не устанавливаем заголовок `User-Agent` (в release notes 2.15.0 не подтверждён как обязательный).
- Не добавляем prefix-валидацию/предупреждения о Legacy-ключах в UI.
- Не задействуем новые методы 2.16/2.17 (дивиденды/сплиты/купоны, `triggered_order_id`).
- Не удаляем поддержку старых длинных токенов.
- `source_app_id` не выносим в env-конфиг — оставляем константой в коде.

## Acceptance Criteria
- [ ] `go.mod` указывает `v0.0.0-20260707135128-ee013ef14834`, `go mod tidy` чистый.
- [ ] `go build ./...` компилируется; `go test ./...` и `go test -tags=integration ./api/...` проходят; `make lint` без новых замечаний.
- [ ] `AuthRequest` и `SubscribeJwtRenewalRequest` содержат непустой `SourceAppId`.
- [ ] Обновление токена идёт через стрим `SubscribeJwtRenewal`; таймерный `startTokenRefresh` удалён; есть реконнект с бэкоффом и остановка по `Close()`.
- [ ] Онбординг-тексты/ссылки, `.env.example`, `README.md`, `CHANGELOG.md` отражают новый формат `tapi_sk_` и портал `api.finam.ru/tokens`.
- [ ] (Ручной смоук) Вход реальным коротким ключом `tapi_sk_...` работает: счета загружаются, стрим обновления токена присылает новые JWT.
- [ ] Старый длинный ключ продолжает работать (обратная совместимость).

## Edge Cases
- Новый короткий JWT должен корректно парситься в `getExpiryFromToken` (3 части, claim `exp`) — проверить при смоуке.
- Обрыв стрима `SubscribeJwtRenewal` не должен ронять приложение — только реконнект с бэкоффом; при `Close()` — тихий выход без ошибок в логах.
- Не вводить валидацию, отвергающую старые длинные ключи.
- Маскировка ввода токена (`*`) корректна при любой длине — уже так.
- Первичный `Auth` и стрим `SubscribeJwtRenewal` используют один и тот же секрет и `source_app_id`.

## Dependencies
- SDK `github.com/FinamWeb/finam-trade-api/go@v0.0.0-20260707135128-ee013ef14834`.
- Реальный ключ `tapi_sk_...` (у пользователя) — только для ручного смоука; авто-тесты идут через мок `bufconn`.
- Релиз 2.15.0: https://github.com/FinamWeb/finam-trade-api/releases/tag/Release-2.15.0
