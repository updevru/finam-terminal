# Spec: Автообновление терминала (проверка релизов GitHub + self-update с перезапуском)

## Problem
Терминал распространяется как одиночный бинарник: пользователь ставит его install-скриптом с `fcli.ru` и дальше никак не узнаёт о новых релизах. Версия в шапке (`Finam Terminal v0.13.0`) статична, а релизы выходят регулярно (v0.10.1 → v0.14.0 за полгода). На практике это значит:

- пользователь месяцами сидит на устаревшей сборке, не получая исправлений API-контрактов (например, фикс `TokenDetails` без `Authorization`, из-за которого счета не загружались вовсе);
- узнать об обновлении можно только зайдя на GitHub вручную;
- обновление требует вспомнить и выполнить команду установки заново.

Нужен механизм, который сам замечает новый релиз, ненавязчиво сообщает об этом в интерфейсе и умеет обновиться в один клик — при этом **не замедляя ни запуск, ни работу программы**: сеть до GitHub может быть медленной или недоступной, и это не должно влиять на торговый интерфейс.

## Solution
Новый пакет `updater/` с тремя независимыми слоями и тонкой интеграцией в `main.go` и `ui/`:

1. **Проверка (фон, раз в сутки).** Горутина запрашивает `https://api.github.com/repos/updevru/finam-terminal/releases/latest`, сравнивает semver с `version.Version` и сохраняет результат в `~/.finam-cli/update.json` — рядом с `.env`, где уже лежит токен. Никакой блокировки: старт программы её не ждёт, ошибки сети идут только в лог.
2. **Уведомление.** При запуске состояние читается **из файла** (без сети, мгновенно). Если в нём версия новее текущей — до подъёма TUI показывается диалог «Обновить и перезапустить / Продолжить». В шапке TUI рядом с версией появляется значок `⚡` и актуальная версия; та же информация доступна по горячей клавише `U`, которая открывает модалку обновления в любой момент.
3. **Обновление (self-update).** Программа скачивает ассет своего релиза (`finam-terminal-{os}-{arch}[.exe]`) во временный файл рядом с собой, сверяет SHA256 с `checksums.txt` из релиза, атомарно подменяет собственный бинарник через rename (на Windows — предварительно переименовав работающий `.exe` в `.old`) и перезапускается с теми же аргументами. Логика скачивания повторяет то, что делают install-скрипты `install.sh` / `install.ps1` / `install.cmd`, но без внешнего shell, без `sudo` и без изменения `PATH`.

Проверка включается только для релизных сборок: если `version.Version == "dev"` (плейн `go build`, `go run`, Docker-образ — его Dockerfile не инжектит ldflags), весь механизм молчит целиком.

## Requirements

### 1. Пакет `updater/` — сравнение версий
- `IsRelease(v string) bool`: `true` только для распарсенного semver-тега (`v0.14.0`, `0.14.0`); `dev`, `dev (a1b2c3d)`, пустая строка → `false`.
- `Compare(a, b string) int`: сравнение по MAJOR/MINOR/PATCH, префикс `v` необязателен; pre-release (`v1.0.0-rc1`) младше релиза той же тройки.
- `IsNewer(current, latest string) bool`: `true` только когда обе версии релизные и `latest > current` (downgrade и равенство — `false`; локальная сборка новее релиза не приводит к предложению «обновиться» назад).

### 2. Пакет `updater/` — файл состояния
- Каталог: тот же, где `.env` с токеном — `~/.finam-cli/`. В `config/` выделяется экспортируемый `config.UserConfigDir() (string, error)`, который переиспользуют `saveTokenInternal` и updater (единая точка, без второго хардкода `.finam-cli`).
- Файл `update.json`:
  ```json
  {
    "last_check": "2026-08-25T09:12:33Z",
    "latest_version": "v0.14.0",
    "release_url": "https://github.com/updevru/finam-terminal/releases/tag/v0.14.0",
    "published_at": "2026-08-25T08:00:00Z"
  }
  ```
- `LoadState()`: отсутствующий, пустой или битый JSON → нулевое состояние + `nil` ошибка (файл-кэш никогда не ломает запуск); проблема логируется как `[WARN]`.
- `SaveState()`: атомарная запись (temp в том же каталоге + rename), права `0644`, каталог создаётся с `0755`.
- Ассеты релиза в состоянии **не** храним: при нажатии «Обновить» сеть всё равно нужна, свежий запрос релиза надёжнее устаревшего URL.

### 3. Пакет `updater/` — клиент GitHub Releases
- `FetchLatestRelease(ctx)` → `GET https://api.github.com/repos/updevru/finam-terminal/releases/latest`, заголовки `Accept: application/vnd.github+json`, `User-Agent: finam-terminal/<version>`; без токена (60 запросов/час на IP — при одной проверке в сутки запас 60×).
- Таймаут проверки 10 с; базовый URL — переменная пакета, чтобы тесты подменяли его на `httptest`.
- Разбор: `tag_name`, `html_url`, `published_at`, `assets[] {name, browser_download_url, size}`. Эндпоинт `/latest` по определению не отдаёт draft/pre-release — отдельная фильтрация не нужна.
- Любая ошибка (сеть, 403 rate limit, 5xx, некорректный JSON) → возврат ошибки, лог `[WARN] Update check failed: …`, состояние на диске не меняется, следующая попытка — по обычному расписанию.

### 4. Пакет `updater/` — планировщик фоновой проверки
- `ShouldCheck(state, now)`: `true`, если `now - last_check >= 24h` (нулевое время — тоже `true`).
- `Run(ctx, current string, onNewVersion func(latest string))`: горутина; первая проверка сразу, если срок вышел, иначе сон до срока; далее цикл раз в 24 часа; выход по `ctx.Done()`.
- После успешной проверки — `SaveState`; если `IsNewer(current, latest)` — вызов `onNewVersion` (ровно один раз на найденную версию, повторные проверки той же версии колбэк не дублируют).
- Запуск горутины **не блокирует** `main`: старт TUI не ждёт ни сети, ни файла; при `!IsRelease(current)` `Run` немедленно возвращается, не создавая ни горутины, ни файла.

### 5. Пакет `updater/` — выбор ассета и целостность
- `AssetName(goos, goarch string) (string, error)`: `linux/amd64` → `finam-terminal-linux-amd64`, `darwin/amd64|arm64` → `finam-terminal-darwin-{arch}`, `windows/amd64` → `finam-terminal-windows-amd64.exe`; остальные комбинации (в т.ч. `linux/arm64`, `windows/arm64`) → ошибка «для платформы X/Y готовой сборки нет».
- Целостность: из релиза скачивается ассет `checksums.txt` (строки `<sha256>␠␠<filename>`), хеш скачанного файла считается на лету (`io.MultiWriter` + `sha256`) и сверяется. Несовпадение → ошибка, временный файл удаляется, текущий бинарник не тронут.
- Фоллбек для релизов, выпущенных до этого трека (`checksums.txt` отсутствует): сверка размера скачанного файла с `asset.size` из GitHub API.
- В `.github/workflows/release.yml` в job `release` перед созданием релиза добавляется генерация `checksums.txt` (`sha256sum finam-terminal-* > checksums.txt` в каталоге `dist/`) — он попадает в релиз существующим `files: dist/*`.

### 6. Пакет `updater/` — применение обновления
- `SelfUpdate(ctx, rel *Release, progress func(done, total int64)) error`:
  1. `os.Executable()` + `filepath.EvalSymlinks` — реальный путь бинарника;
  2. проба записи в его каталог; при отказе — `ErrNotWritable` с готовой командой ручного обновления под текущую ОС (`curl -fsSL https://fcli.ru/install.sh | bash` / `irm https://fcli.ru/install.ps1 | iex`);
  3. скачивание ассета в `<dir>/.finam-terminal-update-<pid>.tmp` (тот же каталог = та же ФС, rename атомарен), таймаут 5 минут, `progress` для консольного индикатора, `defer` удаляет temp при любой ошибке;
  4. сверка SHA256 (или размера — фоллбек);
  5. `chmod 0755` на Unix (на Windows — no-op);
  6. подмена: `rename(exe → exe.old)`, затем `rename(tmp → exe)`; при неудаче второго rename — откат `rename(exe.old → exe)` и ошибка; на Unix `exe.old` удаляется сразу, на Windows остаётся (работающий `.exe` удалить нельзя).
- `CleanupStaleBackup()` — удаление `exe.old` при старте программы, ошибки игнорируются (первый запуск после обновления на Windows подчищает за собой).
- `Restart(exePath string) error`: Unix — `syscall.Exec(exePath, os.Args, os.Environ())` (тот же PID и терминал); Windows — `exec.Command` с унаследованными stdio, `Start()`, затем `os.Exit(0)`. Разделение по build-тегам в стиле существующего `platform/console_windows.go` / `console_others.go`; точка вызова спрятана за переменной пакета, чтобы тест проверил аргументы без реального exec.

### 7. UI — диалог при запуске
- `ui.NewUpdatePromptApp(current, latest string) *UpdatePromptApp` — короткое tview-приложение (по образцу `ui.NewSetupApp`) с модалкой:
  ```
  ⚡ Доступна новая версия Finam Terminal

     Установлена:  v0.13.0
     Актуальная:   v0.14.0

     [ Обновить и перезапустить ]   [ Продолжить ]
  ```
  `Run()` возвращает выбор пользователя (`bool`). По умолчанию выделена «Продолжить»; `Esc` = «Продолжить».
- Показывается в `main.go` **после** `ui.PrintConsoleSplash()` и **до** `ui.RunStartupSteps` — незачем подключаться к брокеру, если сейчас будет перезапуск.
- Содержимое диалога — только версии (release notes не тянем).

### 8. UI — индикатор в шапке и клавиша `U`

> **Уточнено 2026-08-25 по итогам ручной проверки:** из индикатора убрана подсказка «— нажмите U». Значок и номер доступной версии остаются: шапка с обновлением рендерится как ` Finam Terminal v0.13.0 [yellow]⚡ v0.14.0[-] `. Всё остальное в пункте (клавиша `U`, `SetUpdateAvailable`, `SetDynamicColors(true)`) — в силе.
- Чистая функция `headerLabel(current, latest string) string` в `ui/components.go`: без обновления — ` Finam Terminal v0.13.0 `; с обновлением — ` Finam Terminal v0.13.0 [yellow]⚡ v0.14.0 — нажмите U[-] ` (header получает `SetDynamicColors(true)`); существующее правило про префикс `v` для голых числовых версий сохраняется.
- `App.SetUpdateAvailable(latest string)` — потокобезопасный сеттер (вызывается из фоновой горутины через `QueueUpdateDraw`), перерисовывает шапку.
- Клавиша `u`/`U`/`г`/`Г` в главном экране (свободна: заняты `q r a x e c s 1-4`, `Ctrl+R`, `Esc`) открывает модалку «У вас v0.13.0, доступна v0.14.0» с кнопками «Обновить и перезапустить» / «Отмена». Если обновления нет — статус-бар пишет «Установлена последняя версия».
- Подтверждение в модалке ставит флаг `App.updateRequested` и вызывает `app.Stop()`; сам апдейт выполняется в `main.go` после возврата из `app.Run()` — из-под tview процесс не подменяем.

### 9. main.go — сборка потока
- В начале: `updater.CleanupStaleBackup()` (тихо).
- После сплэша, только при `updater.IsRelease(version.Version)`:
  - `state := updater.LoadState()`; при `IsNewer` → диалог п.7; при согласии → `runUpdateFlow` (консольный прогресс по образцу `RunStartupSteps`) → `Restart`;
  - `ctx` + `go updater.Run(ctx, version.Version, onNewVersion)`, где `onNewVersion` через `QueueUpdateDraw` зовёт `app.SetUpdateAvailable`.
- После `app.Run()`: если `app.UpdateRequested()` → тот же `runUpdateFlow` + `Restart`.
- Любая ошибка обновления: печать понятного текста (в т.ч. команды ручной установки), пауза 2 с, обычное продолжение работы — обновление никогда не мешает торговать.

### 10. Документация
- Новый раздел мануала `docs/user_manual/updates.md`: как работает автопроверка (раз в сутки, в фоне, не тормозит запуск), что значит `⚡` в шапке, диалог при запуске, клавиша `U`, что происходит при обновлении (скачивание → проверка контрольной суммы → замена → перезапуск), где лежит `~/.finam-cli/update.json`, как обновиться вручную install-скриптом, почему в dev/Docker-сборке проверки нет.
- `docs/user_manual/index.md` — пункт в списке возможностей и в содержании; `interface-overview.md` — описание индикатора в шапке; списки горячих клавиш — клавиша `U`.
- `README.md` — раздел «Обновление», `CHANGELOG.md` — запись релиза, `CLAUDE.md` — описание пакета `updater/` и файла состояния.

## Acceptance Criteria
- [ ] На релизной сборке старее последнего релиза при запуске появляется диалог с обеими версиями и двумя кнопками; «Продолжить» поднимает обычный TUI, «Обновить» скачивает, заменяет бинарник и перезапускает программу — новая версия видна в шапке.
- [ ] В шапке TUI рядом с версией виден `⚡` и номер актуальной версии; клавиша `U` открывает модалку обновления; при отсутствии обновления `U` пишет в статус-бар, что установлена последняя версия.
- [ ] Проверка выполняется в фоне не чаще раза в сутки; результат лежит в `~/.finam-cli/update.json` рядом с `.env`; повторный запуск в тот же день сети не касается.
- [ ] Полностью отключённая сеть (или недоступный GitHub) не замедляет запуск и работу: TUI поднимается штатно, в логе `[WARN]`, индикатора нет.
- [ ] Скачанный бинарник с испорченной контрольной суммой отвергается, текущий остаётся рабочим.
- [ ] На dev-сборке (`go run main.go`, Docker) ни диалога, ни индикатора, ни файла состояния, ни сетевых запросов.
- [ ] Нет прав на запись в каталог установки → понятное сообщение с командой ручного обновления, программа продолжает работать.
- [ ] Юнит-тесты покрывают semver, состояние, GitHub-клиент (httptest), планировщик, выбор ассета, скачивание+SHA256, подмену и откат, рендер шапки и модалки; `go test ./...`, `go test -tags=integration ./api/...`, `-race`, `make lint` — зелёные, покрытие нового пакета > 80%.
- [ ] `checksums.txt` присутствует в артефактах релизного workflow.
- [ ] Мануал содержит раздел об обновлении, а `index.md` — ссылку на него.

## Edge Cases
- **Битый/пустой `update.json`** → трактуется как «проверок не было», перезаписывается при следующей проверке.
- **`latest` старше текущей версии** (локальная сборка свежее релиза) → ничего не показываем.
- **Rate limit GitHub (403)** → `[WARN]` в лог, следующая попытка через сутки.
- **Платформа без готового ассета** (`linux/arm64`, `windows/arm64`) → индикатор показывается, но обновление отказывает с текстом «для linux/arm64 сборки нет, соберите из исходников».
- **Каталог только для чтения** (`/usr/local/bin` без root) → `ErrNotWritable` + команда ручного обновления.
- **Обрыв связи посреди скачивания** → temp удаляется, бинарник цел, сообщение об ошибке.
- **Windows: работающий `.exe`** → подмена через `.old`, чистка при следующем старте; повторное обновление в той же сессии переиспользует ту же схему.
- **Две копии терминала одновременно** → temp-файл содержит PID, конфликтов имён нет; последний rename побеждает, оба бинарника валидны.
- **Пользователь отказался** → в этой сессии диалог больше не поднимается (только `⚡` и клавиша `U`), при следующем запуске предложение повторяется.
- **`~` недоступен** (`os.UserHomeDir` вернул ошибку) → проверка молча выключается, запуск не страдает.
- **Свежая версия найдена во время работы** → `⚡` зажигается без перезапуска и без модальных окон поверх торгового интерфейса.

## Dependencies
- Только стандартная библиотека Go: `net/http`, `encoding/json`, `crypto/sha256`, `os`, `os/exec`, `syscall`, `path/filepath`, `runtime`. Новых модулей в `go.mod` не добавляется.
- GitHub Releases API репозитория `updevru/finam-terminal` (публичный, без аутентификации).
- Существующие ассеты релиза из `.github/workflows/release.yml` + новый `checksums.txt`.
- `version` (текущая версия), `config` (каталог `~/.finam-cli`), `ui` (диалоги и шапка).

## Non-Goals
- Молчаливое автообновление без подтверждения пользователя.
- Каналы обновлений (beta/pre-release), откат на предыдущую версию по требованию, дельта-патчи.
- Проверка GPG-подписи или кодовой подписи бинарника (сверяем только SHA256 из релиза).
- Обновление Docker-образа изнутри контейнера (`docker pull` — задача пользователя).
- Настройки/флаги отключения автопроверки — по решению пользователя механизм всегда включён для релизных сборок.
- Обновление через install-скрипты `fcli.ru` как основной путь: они остаются документированным ручным способом.
