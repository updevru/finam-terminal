# Spec: Вкладка «Индекс» — витрина бумаг Индекса МосБиржи

## Problem

Пользователь терминала не может купить бумагу, если не знает её тикер или название: поиск (`S`) помогает только тем, кто уже знает, что ищет. Нужна «витрина» ликвидных бумаг, которая подсказывает, что вообще можно купить, — с ценой и изменением за торговую сессию, откуда в один шаг доступны профиль инструмента и стандартное окно покупки.

Жёсткое ограничение заказчика: **стабильная работа без риска упереться в лимиты Finam API**. Если фичу нельзя реализовать в рамках лимитов — её не делаем вовсе.

## Solution

Четвёртая вкладка **Index** (Positions | History | Orders | Index) со списком бумаг из состава Индекса МосБиржи. Состав берётся из API: `AssetsService.GetConstituents` (метод есть в текущей версии SDK из go.mod) — символ, название, сектор и вес каждого компонента. По каждой бумаге: тикер, название, цена, изменение за сессию (абс. и %), вес, дневной объём. `Enter` — профиль инструмента, `A` — стандартная модалка заявки.

### Источник состава: GetConstituents — результаты разведки на реальном API (2026-08-26)

Одноразовый скрипт с реальным токеном (авторизация → bulk `Assets` → пробы `GetConstituents`) установил:

- ✅ **`IMOEX@RTSX` поддержан**: 46 компонентов одной страницей, символы формата `SBER@MISX`, русские названия («Сбербанк»), сектора («Финансы»), веса заполнены. Это основной и единственный индекс трека.
- ❌ `IMOEX@MISX`, `MOEXBC@MISX` («Голубые фишки») → `NotFound: Constituents not found`.
- ✅ Американские `NDX@_SCI` (102) и `SPX@_SP` (503) тоже работают — в скоуп не входят (торгуемость их компонентов у брокера сомнительна, а подписка на 500+ символов — неоправданный риск), но архитектура позволяет добавить их константой позже.
- ⚠️ Сам индекс `IMOEX@RTSX` в bulk-списке `Assets` **отсутствует** (там ровно один инструмент типа INDICES — NDX@_SCI) → символ индекса нельзя найти через кеш активов, он фиксируется **зашитой константой** `{Symbol: "IMOEX@RTSX", Name: "Индекс МосБиржи"}`. Состав при этом всегда актуальный — из API.
- ⚠️ Шкала весов неочевидна (SBER = 0.0080, сумма долей заметно меньше 1) — сортировка по убыванию веса корректна в любой монотонной шкале, но отображать вес как «% в индексе» без проверки нормировки нельзя; интерпретация уточняется при имплементации (при сомнении показывать сырое значение или скрыть колонку).

Пагинация (`cursor`/`next_cursor`) в коде обязательна по контракту API, даже если сегодня IMOEX приходит одной страницей.

### Анализ лимитов API (ключевое проектное решение)

Подтверждённые факты (официальная документация api.finam.ru + разведка, 2026-08-26):
- Лимит unary-запросов: **200 запросов в минуту на каждый метод** (у `GetConstituents`, `LastQuote` и т.д. — свои независимые бюджеты).
- `SubscribeQuoteRequest.symbols` — список символов; документированного лимита на количество символов в подписке нет. Соединения рвутся раз в сутки (реконнект уже реализован).
- Поле `Quote.change` = «Изменение цены (last минус close)», `Quote.close` = «Цена закрытия. Дневная» (proto SDK) — **изменение за сессию приходит в каждой котировке бесплатно**, и в `LastQuote`, и в стриме.

Бюджет вкладки по дизайну (состав IMOEX — 46 бумаг):

| Данные | Источник | Стоимость API |
|---|---|---|
| Состав индекса (символы, имена, сектора, веса) | `GetConstituents("IMOEX@RTSX")` при первом входе на вкладку; кеш в памяти на сессию (TTL 24ч, stale-on-error) | 1–2 запроса в сутки |
| Дорезолвинг тикера для заявки | Символ компонента уже полный (`SBER@MISX`) | 0 запросов |
| Цена, изменение, объём | Существующий стрим `SubscribeQuote`: символы компонентов добавляются в подписку **только пока вкладка активна**; при подписке сервер сразу шлёт снапшот по каждому символу | 0 unary-запросов |
| Fallback при упавшем стриме | Разовый батч `LastQuote` по составу при входе на вкладку, ручной `R`, авто — не чаще 1 раза в 60с и только при активной вкладке | ≤ 46 вызовов `LastQuote` за раз, ≤ ~92/мин в худшем случае — внутри лимита 200/мин метода |
| Профиль / покупка | Существующие пути (`OpenProfileForSymbol`, `OpenOrderModalWithTicker` + `warmLotSizeAsync`) | без изменений |

Итого: в штатном режиме (живой стрим) вкладка добавляет **1–2 запроса состава в сутки и ноль unary-запросов на котировки**, лишь расширяя уже существующую подписку. Периодический поллинг котировок индекса отвергнут расчётом: 46 символов × 12 тиков/мин = 552 вызова/мин >> 200/мин.

### Принятые решения и отклонённые альтернативы

1. **Список индексов — зашитая константа `{Symbol, Name}`; состав — из API с кешем на сессию.** Разведка показала: символ `IMOEX@RTSX` в bulk-активах отсутствует, автообнаружение индексов невозможно, а из российских индексов метод отдаёт только IMOEX → в треке ровно один индекс, без переключателя. Имя «Индекс МосБиржи» зашито (визуальный заголовок вкладки).
   - *Запасной план не нужен:* встроенный статический состав отброшен — API подтверждённо отдаёт состав IMOEX.
   - *Отклонено:* MOEX ISS API в рантайме — новая внешняя зависимость и точка отказа; противоречит требованию стабильности.
   - *Отклонено:* NDX/SPX в этом треке (см. разведку).
2. **Котировки — через общий существующий стрим**, а не отдельное соединение: переиспользуются менеджер, бэкофф, коалесинг и фоллбек; символы индекса участвуют в подписке только при активной вкладке.
3. **Кеш состава — stale-on-error:** ошибка рефетча по TTL не стирает прежний состав; ошибка первой загрузки → сообщение на вкладке + повтор по `R`. Никаких ретраев в цикле.
4. **Защита существующей функциональности:** если после добавления индексных символов стрим не поднимается (недокументированный лимит символов, деградация сервера), индексные символы исключаются из подписки до конца сессии — котировки позиций возвращают себе рабочий стрим, вкладка живёт на ограниченном фоллбеке.
5. **Никакого сетевого резолвинга в рендере:** лот прогревается существующим `EnsureLotSize` только при открытии модалки заявки.

## Requirements

### Функциональные
- Вкладка Index в существующем TabbedView, циклическая навигация ←/→ по 4 вкладкам; заголовок таблицы показывает «Индекс МосБиржи».
- Список бумаг индекса: Ticker, Name, Price (last), Chg (абс.), Chg% (от дневного close), Weight, Volume. Сортировка по весу убыв. (при отсутствии весов — по алфавиту). Рост — зелёным, падение — красным, нет данных — «—».
- Первый вход на вкладку → асинхронная загрузка состава со статусом «Loading…»; ошибка → сообщение на вкладке, повтор по `R`.
- `Enter` — профиль инструмента (`OpenProfileForSymbol`); `A`/`Ф` — стандартная модалка заявки (`OpenOrderModalWithTicker`) с корректным лотом; `R` — обновление (состав при ошибке/протухшем TTL + котировки). Статус-бар показывает подсказки вкладки.
- Котировки realtime при живом стриме; при упавшем — фоллбек по правилам из таблицы бюджета.
- Данные вкладки не зависят от выбранного счёта.

### Технические
- `models.Quote` дополняется полем `Change` (маппинг в `quoteToModel`; `mergeQuote` уже переносит `Change`).
- `models.IndexConstituent{Symbol, Ticker, Name, Sector, Weight}`; `Client.GetIndexConstituents(indexSymbol)` — полная выборка через пагинацию (защитный предел страниц), кеш в памяти TTL 24ч, stale-on-error.
- Список индексов — константа в UI: `[{Symbol: "IMOEX@RTSX", Name: "Индекс МосБиржи"}]`; добавление индекса в будущем = добавление элемента константы.
- `MockAssetsServer.GetConstituents` в testserver: фикстуры с пагинацией и per-call инъекцией ошибок.
- Котировки индекса хранятся в отдельной карте UI (`indexQuotes`), наполняются из общего inbox стрима и из фоллбек-батча.
- При `ResourceExhausted` от `LastQuote` автополлинг индекса отключается до конца сессии (ручной `R` остаётся), статус-бар сообщает об этом.
- TDD, покрытие ≥80% нового кода, race-детектор чист, golangci-lint чист.

## Acceptance Criteria
- [x] Разведка зафиксировала точные символы: `IMOEX@RTSX` — единственный поддержанный российский индекс (46 бумаг, символы/имена/веса подтверждены).
- [ ] Вкладка Index показывает 46 бумаг IMOEX с названиями; заголовок — «Индекс МосБиржи».
- [ ] При живом стриме цены/изменения обновляются в реальном времени; наполнение вкладки после входа ≤ ~2с (снапшоты подписки), котировки — без единого unary-вызова.
- [ ] Повторные входы на вкладку в течение сессии не вызывают `GetConstituents` (кеш, счётчик мока).
- [ ] При остановленном стриме вкладка наполняется разовым батчем и обновляется по `R`; автообновление не чаще 1/60с и только при активной вкладке.
- [ ] `Enter` открывает профиль выбранной бумаги; `A` — стандартную модалку заявки с корректным лотом; заявка проходит существующим путём.
- [ ] Уход с вкладки возвращает подписку к набору позиций (видно по логу переподписки); котировки позиций не деградируют ни в одном сценарии, включая отказ подписки с индексными символами.
- [ ] `go test ./...`, `go test -tags=integration ./api/...`, `-race` обеих сюит и `make lint` — зелёные.

## Edge Cases
- `GetConstituents` вернул ошибку при первой загрузке → сообщение на вкладке, ни одного автоматического ретрая, повтор только по `R`.
- Ошибка рефетча по истёкшему TTL → старый состав сохраняется (stale-on-error), `[WARN]` в лог.
- Компонент с пустым/битым символом (без `@`) → строка скрыта (`normalizeSymbols` его и в подписку не пустит), один `[WARN]` на символ за сессию.
- Пустой ответ (0 компонентов) → трактуется как ошибка загрузки (сообщение + `R`), кеш не отравляется пустотой.
- Котировка ещё не пришла → «—» во всех числовых колонках; `close` = 0 или отсутствует → Chg% = «—» (никаких NaN/Inf).
- Выходной/вечерняя сессия: change может быть нулевым — отображается как есть (0.00 нейтральным цветом).
- Быстрое переключение вкладок туда-обратно → лишних переподписок нет сверх фактических смен набора (`SetQuoteSymbols` дедупит равные наборы, переподписка без down-события).
- Смена счёта при активной вкладке → подписка = позиции нового счёта ∪ индекс.
- Открытие профиля поверх вкладки → символ профиля добавляется к набору (существующее поведение сохраняется).
- Пагинация зациклилась/слишком длинна → защитный предел страниц (например, 10), `[WARN]`, используется собранное.
- Веса вне ожидаемой нормировки → сортировка работает на любых значениях; формат отображения выбирается по факту данных (см. разведку).

## Out of Scope
- Значение самого индекса в пунктах (`IMOEX@RTSX` отсутствует в bulk-активах; `LastQuote` по нему не проверялся — возможное будущее расширение).
- Другие индексы: MOEXBC не поддержан API (`NotFound`), NDX/SPX работают, но не в этом треке — добавляются элементом константы.
- Переключатель индексов в UI (в треке один индекс; появится вместе со вторым индексом).
- Покупка «одной кнопкой» без модалки; продажа из вкладки.
- Колонка Sector — опционально при свободной ширине, не критерий приёмки.

## Dependencies
- Ничего нового: SDK `github.com/FinamWeb/finam-trade-api/go` v0.0.0-20260813094515 (уже в go.mod, содержит `GetConstituents`), существующие стрим-менеджер, кеш активов, модалка заявки, профиль.
