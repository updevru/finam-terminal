# Обновление программы

Finam Terminal сам следит за выходом новых версий и умеет обновляться в один шаг: скачать новый файл программы, проверить его и перезапуститься. Заходить на GitHub и вспоминать команду установки больше не нужно.

## Как работает проверка

Раз в сутки программа в фоне спрашивает у GitHub, какая версия сейчас последняя.

- Проверка идёт **в фоне** и никогда не задерживает ни запуск, ни работу терминала.
- Если сети нет или GitHub недоступен — программа просто работает дальше, а в журнале `finam-terminal.log` появляется строка `[WARN] Update check failed: …`. Никаких окон с ошибками.
- Чаще одного раза в сутки запросы не отправляются: результат последней проверки хранится в файле, и повторный запуск в тот же день сети не касается.

Найденная версия никак не показывается во время работы: ни значков в шапке, ни всплывающих окон поверх торгового интерфейса. О новой версии программа сообщает один раз — диалогом при следующем запуске.

## Диалог при запуске

Если на момент запуска уже известно о новой версии, до подъёма основного интерфейса появится окно:

```
⚡ Доступна новая версия Finam Terminal

    Установлена:  v0.13.0
    Актуальная:   v0.14.0

    [ Обновить и перезапустить ]   [ Продолжить ]
```

- **Обновить и перезапустить** — программа скачает и установит новую версию, затем перезапустится.
- **Продолжить** — обычный запуск. Это выбор по умолчанию: он же срабатывает по клавише `Esc`.

Если вы отказались, в этом сеансе диалог больше не появится и ничто о новой версии не напомнит — обновиться можно клавишей `U`. При следующем запуске предложение повторится.

## Клавиша U

В главном экране клавиша `U` (или `Г` в русской раскладке) открывает окно обновления в любой момент:

| Клавиша | Действие |
|---------|----------|
| U | Обновить программу до последней версии |

Если обновление доступно, откроется окно с обеими версиями и кнопками «Обновить и перезапустить» / «Отмена». Если установлена последняя версия, в статус-баре появится сообщение «Установлена последняя версия».

## Что происходит при обновлении

1. Программа запрашивает у GitHub сведения о последнем релизе.
2. Скачивает файл для вашей операционной системы рядом с текущим файлом программы — в консоли идёт полоса прогресса.
3. Сверяет контрольную сумму SHA256 скачанного файла с опубликованной в релизе. Если сумма не совпала, файл удаляется, а установленная версия остаётся нетронутой.
4. Заменяет файл программы новым.
5. Перезапускает программу. После перезапуска в шапке видна новая версия.

Обновление никогда не мешает торговать: **любая** ошибка на этом пути (нет сети, обрыв связи, не совпала контрольная сумма, нет прав на запись) выводит понятное сообщение, после чего программа продолжает работу в текущей версии.

### Если нет прав на запись

Когда программа установлена в системный каталог (например, `/usr/local/bin`) и запущена без нужных прав, заменить файл она не сможет. В этом случае вы увидите сообщение с готовой командой ручного обновления — см. следующий раздел.

## Ручное обновление

Обновиться можно и вручную, тем же скриптом установки:

**Linux / macOS:**
```bash
curl -fsSL https://fcli.ru/install.sh | bash
```

**Windows (PowerShell):**
```powershell
irm https://fcli.ru/install.ps1 | iex
```

Этот способ пригодится, если автообновление недоступно: нет прав на запись в каталог установки или для вашей платформы нет готовой сборки (например, `linux/arm64` — такие сборки в релизы не выкладываются, программу нужно собрать из исходников).

## Где хранится результат проверки

Файл `update.json` лежит в том же каталоге, что и файл с токеном:

- Linux / macOS: `~/.finam-cli/update.json`
- Windows: `C:\Users\<Имя>\.finam-cli\update.json`

Внутри — время последней проверки, номер последней версии и ссылка на страницу релиза:

```json
{
  "last_check": "2026-08-25T09:12:33Z",
  "latest_version": "v0.14.0",
  "release_url": "https://github.com/updevru/finam-terminal/releases/tag/v0.14.0",
  "published_at": "2026-08-25T08:00:00Z"
}
```

Файл можно спокойно удалить — программа просто выполнит проверку заново при следующем запуске. Повредить работу терминала он не может: если файл испорчен, он считается отсутствующим.

## Почему в dev-сборке проверок нет

Механизм включается только для релизных сборок — тех, что скачаны из релизов GitHub или установлены скриптом. Если программа запущена из исходников (`go run main.go`, `go build`) или в Docker-образе, версия отображается как `dev`, и тогда:

- проверки не выполняются и запросов в сеть нет;
- файл `update.json` не создаётся;
- диалог при запуске не появляется, а клавиша `U` сообщает, что установлена последняя версия.

Такой сборке просто не с чем сравнивать свою версию — обновляйте её через `git pull` и пересборку, а Docker-образ через `docker pull`.
